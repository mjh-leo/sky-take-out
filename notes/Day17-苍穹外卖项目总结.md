# Day17 - 苍穹外卖项目总结

## 一、项目总览

一个**前后端分离的完整外卖点餐系统**

**双端结构：**

| 端 | 形态 | 功能 |
|----|------|------|
| 管理端 | Web 页面（Vue，Nginx 部署） | 员工/分类/菜品/套餐管理、订单管理、数据统计、导出报表 |
| 用户端 | 微信小程序 | 微信登录、浏览菜品、购物车、下单支付、历史订单、催单 |

**一条数据链路：**
```
小程序 / Web → Nginx（静态资源+反向代理）→ SpringBoot（Controller→Service→Mapper）
                                                    ↓
                                      MySQL（正式数据）+ Redis（缓存）
```

## 四、核心机制串联（知识图谱）

### 1. 鉴权链路（贯穿全项目）
```
登录（账号密码/MD5 或微信 code）→ 签发 JWT → 请求带 token
    → 拦截器解析 token → ThreadLocal 存用户 id → Controller/Service 即用即取
    → afterCompletion 清理 ThreadLocal（防线程池串号）
```
### 2. 缓存链路
```
查 Redis → 命中直接返回 / 未命中查 MySQL → 回写 Redis → 数据变更时删缓存 → 过期兜底
```
（店铺状态、菜品、套餐都走这套，SpringCache 用注解封装了它）
### 3. 订单状态机
```
待付款 → 待接单 → 已接单 → 派送中 → 已完成
   ↘         ↘
 超时取消    拒单（已支付要退款）
```
每个状态操作前都要校验当前状态，配套动作要齐全（退款/原因/时间）。
### 4. 实时推送链路（来单/催单）
```
客户支付 → 后端构造 {type, orderId, content} JSON → WebSocket 推送
    → 管理端浏览器解析 → 按 type 播放提示音（new Audio().play()）+ 弹窗
```
### 5. 数据分层设计
```
Entity（对表）→ DTO（接收入参）→ VO（返回前端）
公共字段（create_time/create_user/update_time/update_user）→ AOP 自动填充
```
