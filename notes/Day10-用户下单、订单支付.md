## 二、用户下单

### 1. 业务流程

下单业务比较复杂，步骤：

1. **校验**：地址不能为空、购物车不能为空
2. **插订单表**：orders 表插 1 条（订单号、用户id、总金额、状态、地址等）
3. **插订单详情表**：order_detail 表插 N 条（购物车里每个商品一条）
4. **清空购物车**：下单成功后购物车清空
5. **返回 VO**：订单号等信息给前端

## 三、微信支付

### 1. 完整支付流程

| 步骤 | 谁 → 谁 | 干什么 |
|------|---------|--------|
| 1-3 | 用户 → 小程序 → 后端 | 用户下单，后端创建订单，返回订单号 |
| 4-6 | 后端 → 微信 | 后端调微信 JSAPI 下单接口，拿到 prepay_id |
| 7-8 | 后端 | 对支付参数签名，返回给小程序 |
| 9-12 | 用户 → 微信 | 用户确认支付，小程序调起微信支付，输入密码，微信返回结果 |
| 13-14 | 微信 → 后端 | **微信主动回调商户系统**，通知支付结果，后端更新订单状态 |

### 2. 两个关键接口

**① JSAPI 下单（后端调微信）：**
```
POST https://api.mch.weixin.qq.com/v3/pay/transactions/jsapi
```
传商户号、订单号、金额、openid、回调地址，微信返回 `prepay_id`（预支付会话标识，有效期2小时）。

**② 小程序调起支付（wx.requestPayment）：**
小程序拿到后端返回的参数，调用微信 API 弹起支付密码框：
```javascript
wx.requestPayment({
    timeStamp: "...",
    nonceStr: "...",
    package: "prepay_id=xxx",
    signType: "RSA",
    paySign: "..."
})
```

### 3. 两个问题

**Q: 调用过程怎么保证数据安全？**
- 所有请求都用 HTTPS
- 商户系统调微信接口时用 **API 证书**（双向认证）
- 关键参数要**签名**，防篡改
- notify_url 回调也要验签，防止有人伪造支付成功通知

**Q: 微信怎么回调到本地开发的电脑？**
- 微信服务器要能访问到你的后端接口
- 本地开发用**内网穿透工具**（如 cpolar、ngrok），把本地端口映射成一个公网域名
- 微信请求这个域名 → 穿透到你本地电脑

## ⚠️ 避坑 Tips

### 1. 微信支付的坑
- **notify_url 必须是公网能访问的地址**。本地开发要内网穿透
- **回调是异步的**。用户付完钱，微信可能过几秒才通知你，不能依赖前端"支付成功"页面来改订单状态
- **回调要做幂等**。微信可能重复发通知，你要判断订单是不是已经是已支付状态了，不能重复处理
### 2. 订单设计的坑
- **订单要存快照**。地址、商品名称、价格都要在下单时存到订单里，不能关联查询。后面地址改了、菜品涨价了，历史订单不能变
- **订单号要唯一**。项目里用的orders.setNumber(String.valueOf(System.currentTimeMillis()));
  一般用时间戳 + 用户id + 随机数。
- **订单状态机要清晰**：待付款 → 已付款 → 待接单 → 已接单 → 派送中 → 已完成，每个状态能做什么操作要明确

## 🎯 面试高频题

### Q1：微信支付的完整流程是什么？
> **回答框架：**
> 1. 用户在小程序下单，后端创建订单
> 2. 后端调微信 JSAPI 下单接口，传订单号、金额、openid，拿到 prepay_id
> 3. 后端把支付参数签名后返回给小程序
> 4. 小程序调 wx.requestPayment 弹起支付，用户输密码
> 5. 微信支付完成后，**主动回调后端 notify_url**，后端收到通知后更新订单状态为已支付
> 6. 前端通过微信 API 拿到支付结果，跳转到成功页
### Q2：为什么订单里要存地址快照和商品快照？
> **回答框架：**
> 1. **地址快照**：下单时把收货人、手机号、详细地址存到订单表。用户后来改了地址簿，历史订单里的地址不变
> 2. **商品快照**：订单详情里存商品名称、图片、单价。后来菜品涨价了、改名了，历史订单里的价格和名称不变
> 3. **为什么不关联查**：
>    - 一致性：历史订单应该定格在下单那一刻，不能跟着变
>    - 性能：查订单列表不用关联菜品表、地址簿表
>    - 解耦：菜品下架了、地址删了，历史订单还能看
> 4. **和购物车冗余字段一个思路**：用空间换一致性和性能
